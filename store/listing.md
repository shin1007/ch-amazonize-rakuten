# Chrome ウェブストア掲載情報

デベロッパーダッシュボードの各欄にそのまま貼る文面。画像は `store/assets/`（`node tools/store-images.mjs` で作り直せる）。

## ストアの掲載情報

### 名前

```
Amazonize Rakuten
```

### 概要（manifest の description。132文字まで）

言語ごとに `tools/translations/_app.json` に書き、`node tools/build-locales.mjs` で `_locales/<言語>/messages.json` にする。

### 説明

`store/assets/locales/<言語>/description.txt`（ja / en / zh_CN / zh_TW / ko / vi / id）。ストアの説明欄はMarkdownを解釈しないので、記号は「■」「・」だけにしてある。
入稿は `store/config.yaml` を ch-uploader に渡す（`AGENT_INPUT_SPEC.md` を参照）。ネパール語・ビルマ語・シンハラ語はストアの対応言語に無いので入れていない。

### カテゴリ / 言語

- カテゴリ: ショッピング
- 言語: 日本語（既定）に加え en / zh_CN / zh_TW / ko / vi / id

### 画像

`node tools/store-images.mjs` でスクリーンショット（`store/assets/locales/<言語>/screenshots/`） を作る（`STORE_LANG=ko` のように1言語だけも作れる）。スクリーンショットは7言語すべてに用意する（文言は `tools/store-images.mjs` の `TEXT`）。プロモーションタイルは日本語の1組だけ。

| 欄 | ファイル | サイズ |
|---|---|---|
| ストアアイコン | `store/assets/icon.png` | 128x128（絵は96px、周りに16pxの透明な余白） |
| スクリーンショット | `store/assets/locales/<言語>/screenshots/01.jpg` 〜 `05.jpg` | 1280x800 |
| 小さいプロモーションタイル | `store/assets/promo-tile-440x280.jpg`（日本語の1組だけ） | 440x280 |
| マーキープロモーションタイル | `store/assets/marquee-1400x560.jpg`（同上） | 1400x560（任意） |

スクリーンショットの順:

1. 商品ページの3カラム（保存したページに拡張を当てて撮影）
2. Amazonの商品ページに出る楽天のリンクと価格（保存したAmazonのページに拡張を当てて撮影。楽天の候補は見本の応答）
3. Yahoo!ショッピングの商品ページに出るAmazon・楽天の価格（保存したYahoo!のページに拡張を当て、Amazon・楽天は実際に引いて撮影）
4. かご合計パネルとクーポン最適化パネル（ストアの上限が5枚なので1枚に並べる）
5. キャンペーンの一括エントリー（ポップアップ）

4 はログインが要る画面なので、拡張と同じCSSで組んだパネルに見本の金額を入れている（金額は README の「実機での検証状況」で実際に出た数字）。5 のエントリー済み一覧も見本のデータ。

## プライバシーへの取り組み

### 単一用途の説明

```
楽天市場（rakuten.co.jp）でのお買い物を快適にするための拡張機能です。商品ページを見やすく組み直し、かごの合計金額の表示、クーポンの獲得と最適なクーポンの適用、キャンペーンへのエントリー、同じ商品のAmazonでの価格の表示を、楽天市場のページ上で行います。また、Amazon.co.jp の商品ページに、同じ商品の楽天市場へのリンクと価格を表示し、ほしい物リストでは値下げ通知サービス（開発者が運営）への登録を案内します。
```

### 権限が必要な理由

**storage**

```
機能ごとのON/OFF設定と、キャンペーンのエントリー結果（エントリー済み一覧）、キャンペーンの自動スキャンを最後に実行した時刻、商品ページで獲得したクーポンの一覧（クーポン名・ショップ名・商品名・商品ページのURL）、レビュー評価の一時的なキャッシュを保存するために使います。保存先はユーザーのブラウザ内だけです。
```

**declarativeNetRequestWithHostAccess**

```
楽天市場のクーポンAPI（api.coupon.rakuten.co.jp）は、Referer が商品ページでないとログイン中でも未ログインとして応答します。拡張機能のバックグラウンドから商品ページのクーポンを取得・獲得するとき、その通信に限って Referer を商品ページのURLに設定するために使います。タブに属さない通信（拡張機能自身の通信）だけが対象で、ユーザーが開いているページの通信は変更しません。
```

**ホスト権限（https://*.rakuten.co.jp/*）**

```
楽天市場の商品ページ・検索結果・かご・注文確認・キャンペーンの各ページで表示を組み直し、クーポンとキャンペーンの処理を行うために必要です。
```

**ホスト権限（https://www.amazon.co.jp/*）**

```
楽天市場の商品ページで「同じ商品がAmazonではいくらか」を表示するため、およびAmazonの商品ページに楽天のリンクと価格を表示するために使います。商品のJANコードまたは商品名でAmazonの検索結果ページを1回読み、価格・商品名・評価を取り出して楽天のページに表示するだけです。Amazonのページの表示は変更せず、ユーザーのAmazonアカウントにも触れません（Cookieを送らずに取得しています）。Amazonの商品ページでは、商品名・JANコード・型番などを読み、楽天の同じ商品を探すためだけに使います。ほしい物リストのページと、ほしい物リストに追加したときの表示からはリストのIDを読み取り、値下げ通知サービス（nesage.party、開発者が運営）への登録の案内を表示します。案内のボタンを押したときにブラウザがそのページを開くだけで、拡張機能から nesage.party へは通信しません。
```

**ホスト権限（https://store.shopping.yahoo.co.jp/* ・ https://shopping.yahoo.co.jp/search* ・ https://shopping.yahoo.co.jp/category/*）** ※ content_scripts の対象。manifest の host_permissions には入れていない

```
Yahoo!ショッピングの商品ページで、左右キーで商品画像を送れるようにし、同じ商品のAmazonと楽天市場での価格を価格の下に表示するために使います。商品名・JANコード・価格は、ページに埋め込まれた商品データから読みます。検索結果・カテゴリ一覧のページでは、広告（PR）の商品を薄く表示するだけです。Yahoo!のアカウントや注文には触れません。
```

**ホスト権限（https://www.rakuten.ne.jp/gold/*）** ※ content_scripts の対象。manifest の host_permissions には入れていない

```
楽天市場の店のサイト（www.rakuten.ne.jp/gold）のページでは、商品ページに埋め込まれた商品動画が勝手に再生されないよう、自動再生を止めるだけです。表示は変えず、通信も行いません。
```

**ホスト権限（https://amazon-rakuten-link.shin1007.workers.dev/*）**

```
Amazon・Yahoo!ショッピングの商品ページで楽天市場の同じ商品を探すため、および楽天市場・Amazonの商品ページでYahoo!ショッピングの同じ商品を探すため、楽天市場商品検索API・Yahoo!ショッピング商品検索APIの中継サーバー（開発者が運営）へ検索語（JANコード・型番・商品名）を送り、商品名・価格・URLを受け取ります。APIのキーを拡張機能に含めないための中継で、送るのは検索語だけです。Cookie・ログイン情報は送りません。
```

### データの使用

- 収集するユーザーデータ: **「ウェブサイトのコンテンツ」だけにチェックする**（Amazonの商品ページの商品名・JAN等から作った検索語を、中継サーバーへ送るため。config.yaml では `collects: [websiteContent]`）
  - かごの金額やクーポンは、ページの中で読んで表示するだけで、端末の外（開発者のサーバー）へ送らない。
  - Amazonへの通信は、楽天の商品ページから作った検索語（JANコードまたは商品名）で検索結果を読むだけ。Cookieを送らないので、ユーザーのAmazonアカウントとは結び付かない。
  - Yahoo!ショッピングの価格（楽天・Amazonの商品ページ）と、Yahoo!ショッピングの商品ページに出す楽天の価格も同じ中継サーバー経由で、送るのは検索語（JANコード・型番・商品名）だけ。区分は「ウェブサイトのコンテンツ」のまま増えない。
  - Amazonの商品ページでは、検索語（JANコード・ISBN・型番・商品名）だけを中継サーバーへ送る。利用者を識別する情報は付けず、サーバー側で保存しない。送信する以上「収集」に当たるとみなし、「ウェブサイトのコンテンツ」にチェックする。
  - 楽天のAPIへの通信は、ユーザーが楽天市場で普段行うのと同じ、楽天とのやり取り。
  - 注文確認のページの状態には氏名・住所・電話・メール・カード下4桁が入っているが、`state-bridge.js` が金額まわりのキーだけを抜き出し、それ以外は拡張側にも渡さない。
  - ほしい物リストの案内（nesage.party）も同じ。ボタンを押したときにリストのURL付きでブラウザが開くだけで、拡張機能は通信しない。開発版のセルフチェック（`src/lib/health.js`）はストア版では動かず、記録もしない。
  - Amazonへのリンクは、ユーザーがクリックしたときにブラウザが開くだけ（拡張機能が nesage.party へ通信するわけではない）。そのため host 権限の追加は要らず、「収集」の区分も増やさない。ただしポリシー（上記）には、中継ページ経由でタグ付きの移動をすることを書く。
- 次の3点に同意する:
  - 承認されている用途以外で、ユーザーデータを第三者に販売、転送しない
  - アイテムの単一用途と関係のない目的で、ユーザーデータを使用、転送しない
  - 信用力を判断する目的または融資目的で、ユーザーデータを使用、転送しない

## 審査で気をつけること

- **名前に他社の商標（Amazon / Rakuten）が入っている。** ストアのポリシーでは、提携や公式であるかのように見える使い方は「なりすまし」「知的財産権の侵害」として却下されうる。説明の末尾に「楽天グループ・Amazonとは関係ない」旨を入れてあるが、それでも名前で弾かれる可能性はある。弾かれたら「楽天市場をシンプルに」のような、商標を名前の先頭に置かない名前に変える（説明の中で「楽天市場向け」「Amazon風」と書くのは記述的な使用として通ることが多い）。
- **スクリーンショット1・2とマーキーには実在の店舗の商品画像が写っている**（保存した hoyu のページ）。気になるなら `STORE_ITEM=<別の保存名> node tools/store-images.mjs` で差し替える。
- 「検索結果の広告を目立たなくする」は現状なにもしない（README の既知の制約）ので、説明には書いていない。
